# Software Requirements Specification (SRS)
## Daily Micro-Loan Management Web App (KHR Currency)

A specialized Progressive Web App (PWA) tailored for managing daily flat-rate loans (21 or 22-day terms) denominated in Khmer Riel (KHR), with mobile-optimized collection workflows, automated amortization schedules, and real-time dashboard analytics.

---

## 1. System Architecture & Tech Stack

* **Frontend:** Next.js / React (TypeScript), Tailwind CSS (Mobile-First UI), Lucide Icons
* **Backend:** Node.js (Next.js API Routes / Express)
* **Database:** PostgreSQL (Cloud SQL or Supabase / Neon)
* **Cloud Infrastructure:** Google Cloud Platform (Cloud Run, Cloud Storage for media, Custom Domain with SSL)
* **Notification Layer:** Telegram Bot API (Daily morning collection rosters & evening unpaid delinquency alerts)
* **Base Currency:** Khmer Riel (KHR / ៛)

---

## 2. Core Functional Modules

### Feature 1: Mobile-First Operational Dashboard
Real-time financial visibility designed for mobile screen usability:
* **Active Borrowers & Outstanding Debt:**
  * Total active client count for the current month.
  * Total outstanding principal + interest balance in KHR.
* **Monthly Loan Disbursements:**
  * Count of new loans disbursed within the current month.
  * Total capital disbursed in KHR within the current month.
* **Monthly Interest Revenue:**
  * Cumulative interest actually collected within the active month (KHR).
* **Daily Collection Schedule:**
  * List of clients scheduled for repayment today with individual daily due amounts in KHR.
* **Delinquency / Missed Payment Tracking:**
  * List of clients who failed to pay today, displaying their phone number and total overdue KHR amount.

---

### Feature 2: Customer & Loan Origination (21 / 22-Day Terms)
* **Customer Profile Requirements:**
  * Full Name (Khmer & Latin)
  * Gender (`Male` / `Female`)
  * Occupation / Business Type
  * Phone Number
  * National ID Card (Khmer ID) Number
  * Document Uploads (Direct to Google Cloud Storage):
    * Customer Portrait Photo
    * National ID Card Image (Front & Back)
    * Signed Loan Contract Agreement
* **Loan Terms & Flat Rate Amortization Engine:**
  * Loan Principal ($P$) in KHR
  * Flat Interest Rate ($r$) as a fixed cycle percentage (e.g., 10%)
  * Term Duration ($N$): Fixed choice of **21 Days** or **22 Days**
  * Automated Formulas:
    $$\text{Total Interest } (I) = P \times r$$
    $$\text{Total Repayment } (A) = P + I$$
    $$\text{Daily Installment } (D) = \frac{P + I}{N}$$
    $$\text{Daily Principal Component } = \frac{P}{N}$$
    $$\text{Daily Interest Component } = \frac{I}{N}$$
* **Schedule Generator:**
  * Generates $N$ chronological records in `loan_schedules` with status initialized to `PENDING`.

---

### Feature 3: One-Tap Repayment Tracking & Payoff Engine
* **Single-Tap Mobile Collection:**
  * Agent selects customer from today's due list and clicks **Record Payment**.
  * Input actual cash received (defaults to daily due amount).
* **Automated Accounting Split:**
  * System splits each transaction into:
    1. Principal Allocation
    2. Interest Income Allocation
* **Early Payoff Option (Pre-Closure):**
  * Calculates remaining uncollected principal and contractual interest balance.
  * Updates all remaining pending schedules to `PAID` with transaction category `PAYOFF`.
  * Closes loan status to `COMPLETED`.

---

### Feature 4: Automated Notification Engine (Telegram Bot)
* **Morning Collection Roster (07:00 AM):**
  * Pushes automated summary to the administrator's Telegram group listing all clients due today and total target collection in KHR.
* **Instant Payment Receipt:**
  * Sends an immediate confirmation log to Telegram upon clicking **Record Payment**.
* **Evening Delinquency Audit (05:00 PM):**
  * Pushes an alert listing all clients who missed today's payment with direct call links.

## 3. Database Schema (PostgreSQL DDL)

```sql
-- 1. Customers Table
CREATE TABLE customers (
    id SERIAL PRIMARY KEY,
    customer_code VARCHAR(20) UNIQUE NOT NULL,
    full_name VARCHAR(100) NOT NULL,
    gender VARCHAR(10) CHECK (gender IN ('Male', 'Female', 'ប្រុស', 'ស្រី')),
    occupation VARCHAR(100),
    phone_number VARCHAR(20) NOT NULL,
    id_card_number VARCHAR(50),
    photo_url TEXT,
    id_card_url TEXT,
    contract_doc_url TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 2. Loans Table
CREATE TABLE loans (
    id SERIAL PRIMARY KEY,
    loan_code VARCHAR(20) UNIQUE NOT NULL,
    customer_id INT REFERENCES customers(id) ON DELETE RESTRICT,
    principal_amount NUMERIC(15, 2) NOT NULL,
    interest_rate_percent NUMERIC(5, 2) NOT NULL,
    total_interest NUMERIC(15, 2) NOT NULL,
    total_amount NUMERIC(15, 2) NOT NULL,
    duration_days INT CHECK (duration_days IN (21, 22)),
    daily_repayment NUMERIC(15, 2) NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    status VARCHAR(20) DEFAULT 'ACTIVE' CHECK (status IN ('ACTIVE', 'COMPLETED', 'PAYOFF', 'DEFAULTED')),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 3. Loan Schedules Table
CREATE TABLE loan_schedules (
    id SERIAL PRIMARY KEY,
    loan_id INT REFERENCES loans(id) ON DELETE CASCADE,
    day_number INT NOT NULL,
    due_date DATE NOT NULL,
    expected_amount NUMERIC(15, 2) NOT NULL,
    expected_principal NUMERIC(15, 2) NOT NULL,
    expected_interest NUMERIC(15, 2) NOT NULL,
    status VARCHAR(20) DEFAULT 'PENDING' CHECK (status IN ('PENDING', 'PAID', 'MISSED', 'PARTIAL')),
    paid_at TIMESTAMP
);

-- 4. Repayments Table
CREATE TABLE repayments (
    id SERIAL PRIMARY KEY,
    loan_id INT REFERENCES loans(id) ON DELETE RESTRICT,
    schedule_id INT REFERENCES loan_schedules(id) ON DELETE SET NULL,
    payment_date DATE NOT NULL,
    paid_amount NUMERIC(15, 2) NOT NULL,
    principal_portion NUMERIC(15, 2) NOT NULL,
    interest_portion NUMERIC(15, 2) NOT NULL,
    payment_type VARCHAR(20) DEFAULT 'DAILY' CHECK (payment_type IN ('DAILY', 'PAYOFF')),
    notes TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
